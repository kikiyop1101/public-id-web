UX Writing (콘텐츠 작성)

퍼블릭아이디 산출물의 글 — 목소리(voice)·상황별 문구 패턴·컴포넌트 라벨 규칙. 형태(폰트·줄바꿈·띄어쓰기)는 korean-typography.md, 내용(무엇을 어떻게 말하나)은 이 문서가 정본이다. 각 컴포넌트 전용 규칙은 해당 컴포넌트 문서의 "콘텐츠 규칙" 섹션에 있다.

Voice — 퍼블릭아이디의 목소리 3특성

특성뜻예
정확하다사실·인증·수치는 정본 표기만, 과장·추정 없음"GREENGUARD GOLD(UL 2818) 인증" (○) / "친환경 최고 등급" (✗)
쉽다관공서 담당자도 아이 보호자도 한 번에 읽힌다"바닥에 붙이는 그래픽 표지" (○) / "노면 부착형 시인성 개선 솔루션" (✗)
간결하다한 문장 한 뜻, 군더더기 없음"3일 안에 시안을 보내드립니다." (○) / "빠른 시일 내에 최대한 신속하게…" (✗)

Tone — 상황별 온도

상황톤감각
제품·서비스 소개자신 있게, 담백하게증명은 숫자·인증이 한다
안내·도움말친절하게, 단계적으로사용자가 헤매지 않게
에러·경고침착하게, 해결 중심으로탓하지 않는다
완료·성공짧게 축하, 다음 행동 제시여운보다 다음 단계

상황별 문구 패턴

에러 문구 — "무엇이 + 왜 + 어떻게" 3요소

예
✅"파일이 10MB를 넘어 올리지 못했습니다. 10MB 이하로 줄여 다시 시도해 주세요."
❌"오류가 발생했습니다." (무엇이 잘못됐는지, 뭘 해야 하는지 없음)
❌"잘못된 입력입니다." (사용자를 탓하는 뉘앙스)
  • 시스템 탓 어휘("실패", "거부됨")보다 상태 서술("올리지 못했습니다")을 쓴다.
  • 폼 검증 에러는 필드 옆 인라인으로(Input 문서 참조), 토스트로 띄우지 않는다.

빈 상태(empty state) — 정적 선언 대신 시작 안내

예
✅"아직 견적 요청이 없습니다. 첫 견적을 요청해 보세요." + [견적 요청하기]
❌"데이터 없음"

알림·완료 문구

  • 완료는 결과 + 다음 행동: "카드뉴스 6장을 저장했습니다. 발행 대기 목록에서 확인하세요."
  • 진행 중은 무엇을 하는지: "발행 중…" ("잠시만 기다려 주세요" 단독 금지 — 뭘 기다리는지 없음).
  • 알림 남발 금지 — 사용자가 요청한 일의 결과만 알린다.

컴포넌트 라벨 공통 규칙

컴포넌트규칙예
Button동사형 2~4어절, 말줄임 금지"견적 요청하기"
Input 라벨명사형, placeholder는 예시값(라벨 대체 금지)라벨 "연락처" / placeholder "010-0000-0000"
Toggle명사형 고정(상태 따라 안 바뀜)"자동 발행" ("켜짐/꺼짐" ✗)
Chip·Badge1~2단어"NEW", "GD2023"
Modal 제목결정을 담은 질문 1문장"발행할까요?"
Tab명사 1~3어절, 같은 품사로 통일"제품 소개 / 시공 사례 / 견적"

표기 정본 (정의는 여기 말고 정본에서)

  • 회사 사실·인증·금지 표현·연락처 표기의 정본은 브랜드 상수 문서(BRAND_CONSTANTS)다 — 이 문서는 규칙을 중복 정의하지 않는다. 자주 걸리는 것만 요지: 인증은 GREENGUARD GOLD(UL 2818)만 표기(KC 보류)('KS'·'환경부 인증' 금지), 잉크는 친환경 라텍스('UV' 금지), 마스코트 이름은 퍼이.
  • 홈페이지 주소를 쓸 때는 public-id.co.kr와 store.public-id.co.kr를 항상 함께 쓴다.
  • 이모지: 인쇄 납품물은 최소화(1~2개), 온라인 콘텐츠는 제한 없음(남발만 지양).

띄어쓰기·줄바꿈 (형태 규칙은 korean-typography가 정본)

  • 조사는 붙이고 의존명사는 띄운다: "할 수 있다", "떠난 지 1년". 숫자+단위는 붙인다: "5개월", "132,000원".
  • 문장이 마침표로 끝나면 줄을 바꾼다(칸이 부족하면 이어 쓴다). 자세한 규칙과 발행 전 체크리스트는 korean-typography.md.
